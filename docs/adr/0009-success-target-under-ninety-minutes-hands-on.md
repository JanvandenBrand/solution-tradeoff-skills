# 9. Success target: under 1.5 hours of hands-on time

## Context

With the old tool, a comparable analysis takes 3 to 4 hours of the user's hands-on time, most of it orchestration: preparing prompts, copying responses, checking files. Reducing that effort is the problem the skill solves.

## Decision

A comparable analysis, from problem definition to a published architecture decision record, should take the user under 1.5 hours of hands-on time.

Reason: the problem being solved is the user's orchestration effort, so hands-on time is measured, not elapsed time.

## Status

Accepted

## Consequences

- Hands-on time is re-measured after the first real run with the skill.
- Steps that add user effort (verification, confirmation, prerequisites) must stay light enough to meet the target.
